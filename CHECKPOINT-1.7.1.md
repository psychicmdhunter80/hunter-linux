## What was found

The 1.7.0 loading screen never ran. `/live/initrd.img` on the delivered ISO
contained the string `plymouth` zero times, while `plymouth 24.004.60-5` was in
the package manifest - the initramfs had been generated in the middle of the
package run, and Debian's plymouth hook exits when no theme has been made the
default. With `quiet` on the command line the result was a black screen for
about 53 seconds, which the boot test did not catch because it accepted the
boot menu as "something drawn".

## What was changed

1. `config/hooks/live/0390-smd-plymouth.hook.chroot` (new): default theme,
   early display drivers, framebuffer fallback, rebuild every initramfs, then
   prove with `lsinitramfs` that it holds `plymouthd` and the theme - failing
   the build if it does not.
2. Panel: ten workspace buttons instead of four plus a text menu; each icon
   shows empty / occupied / current / both, written by the existing
   `hunter-workspaces` subscriber, generated by `tools/make-assets.py`.
3. Tests: the boot test now requires a *splash-shaped* frame (dark with
   content), asserts the initramfs contents, and compares all ten icons with
   i3's own state; the tiling workflow gained a 15-minute stability pass that
   fails on focus changes, relocations, helper restarts, self-triggered
   rearrangements, slow replies or runaway CPU/memory.
4. `VERSION`, every label and every generated picture moved to 1.7.1.
